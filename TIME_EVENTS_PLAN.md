# План временных событий

## Цель

Добавить общие для всех чатов события, которые автоматически действуют в заданные интервалы по одному часовому поясу. Активное событие меняет только параметры попытки `/fish`: шанс успешной поклевки, веса редкости, длительность кулдауна или награду. Данные игрока и каталог рыб не изменяются.

## Расписание и эффекты

Все интервалы ниже указаны в `EVENT_TIMEZONE` (по умолчанию `Europe/Moscow`), левая граница включается, правая не включается. В один момент времени активно не более одного события.

| Событие | Расписание | Эффект |
| --- | --- | --- |
| `Рассветный клёв` | Каждый день, 06:00-08:00 | Шанс успешной поклевки `+20` процентных пунктов, но не выше `100%`. |
| `Золотой час` | Каждый день, 12:00-13:00 | При успешной ловле используются усиленные веса редкости: 1: 45%, 2: 30%, 3: 15%, 4: 7%, 5: 2.5%, 6: 0.5%. |
| `Штиль` | Каждый день, 15:00-16:00 | Длительность нового кулдауна уменьшается вдвое, с округлением вверх до секунды. Уже начатые кулдауны не пересчитываются. |
| `Ночной трофей` | Каждый день, 22:00-23:00 | Рыба редкости 4-6 получает цену `x1.5`; цена округляется до двух знаков после запятой до записи в историю и баланс. |
| `Лунная заводь` | Суббота и воскресенье, 00:00-02:00 | Каждая успешная ловля гарантированно выбирает редкость 2-6 по весам `chance-up`; персональный бонус `/chanceup` при этом не расходуется. |

## Реализация

1. Добавить `src/features/fishing/time-events.ts` с неизменяемым описанием расписания, типами `TimeEvent` и `FishingModifiers`, а также чистой функцией `getActiveTimeEvent(now, timeZone)`. Функция должна принимать время как аргумент, чтобы не зависеть от системных часов и быть полностью тестируемой.
2. В `Config` добавить обязательную строку `eventTimeZone`, читаемую из `EVENT_TIMEZONE`; использовать `Europe/Moscow` как значение по умолчанию в `.env.example`, Compose и README. Валидировать часовой пояс через `Intl.DateTimeFormat` при запуске.
3. Расширить `checkCooldown` параметром фактической задержки попытки. В обработчике `/fish` вычислять модификаторы один раз после чтения каталога и перед проверкой кулдауна, чтобы проверка и запись времени использовали одинаковую длительность. Админская команда `/cd` должна рассчитывать оставшееся время по сохранённой длительности конкретного кулдауна.
4. Для корректного отображения и неизменности уже начатых кулдаунов сохранить их длительность вместе с `lastCatchTime`: добавить поле `delay_seconds` в таблицу кулдаунов, миграцию в `SCHEMA_STATEMENTS` и методы `Repo` для чтения и записи пары времени и задержки. Для существующих строк подставлять обычный `CATCH_DELAY`.
5. Разрешить `tryCatch` и генератору принимать необязательные веса редкости и множитель цены. Сначала применить персональный `/chanceup`, затем гарантированную редкость `Лунной заводи`, затем обычный бросок с модифицированными весами. Событийный множитель цены применять к сформированной рыбе до `recordCatch`.
6. Дополнить сообщение об успешной ловле названием активного события и его кратким эффектом. Добавить публичную групповую команду `/event`, показывающую текущее событие, время окончания и время следующего события; зарегистрировать её в `src/bot.ts` и меню команд.
7. Добавить фоновый планировщик событий, запускаемый из `src/index.ts`. Он проверяет смену события раз в минуту и при его начале отправляет в каждый известный групповой чат одно HTML-сообщение с названием, временем окончания и эффектом. Список чатов получать из `Repo`, а отправку выполнять через экземпляр bot API.
8. Хранить последнюю объявленную пару `eventId` и время начала в базе данных, а не в памяти процесса. Это исключит повторные объявления после рестарта и позволит безопасно запустить только пропущенное уведомление, если бот был выключен в момент начала события. Ошибку отправки в недоступный чат логировать и продолжать рассылку в остальные чаты.
9. Добавить структурированные поля `eventId` и применённые модификаторы в лог разрешённой попытки `/fish`, чтобы баланс событий можно было проверять по логам.

## Проверка

1. Написать тесты `time-events.test.ts` для каждой границы интервала, выходных и перевода UTC-времени в `Europe/Moscow`.
2. Расширить тесты кулдауна: обычная задержка, уменьшенная вдвое задержка, сохранённая задержка не меняется после завершения события.
3. Расширить тесты генератора: веса `Золотого часа`, гарантированная редкость `Лунной заводи`, ценовой множитель `Ночного трофея` и неизменность `/chanceup` во время `Лунной заводи`.
4. Проверить обработчик `/fish` и `/event` на текст ответа, запись цены, расход персонального бонуса и изоляцию состояний по `userId` и `chatId`.
5. Добавить тесты планировщика: одно объявление на событие для каждого чата, отсутствие дублей при следующей проверке и после рестарта, а также продолжение рассылки после ошибки Telegram API в одном чате.
6. Выполнить `bun run typecheck` и `bun test`.
